# 令牌桶流量控制方案总结

## 一、项目当前实现

### 1.1 技术选型

项目采用 **Guava RateLimiter** 进行令牌桶限流，并做了轻量封装。

### 1.2 核心代码

**工具类位置**：`src/main/java/com/wtlx/utils/RateLimiter.java`

```java
public class RateLimiter {
    // 使用 ConcurrentMap 缓存限流器实例，避免重复创建
    private static final ConcurrentMap<String, RateLimiter> limiterCache = new ConcurrentHashMap<>();
    
    // 底层委托给 Guava RateLimiter
    private final com.google.common.util.concurrent.RateLimiter rateLimiter;
    
    private final double permitsPerSecond;

    public RateLimiter(double permitsPerSecond) {
        this.permitsPerSecond = permitsPerSecond;
        this.rateLimiter = com.google.common.util.concurrent.RateLimiter.create(permitsPerSecond);
    }

    // 按 key 获取实例（同一 key 返回同一限流器）
    public static RateLimiter getInstance(String key, double permitsPerSecond) {
        return limiterCache.computeIfAbsent(key, k -> new RateLimiter(permitsPerSecond));
    }

    public boolean tryAcquire() {
        return rateLimiter.tryAcquire();
    }

    public boolean tryAcquire(long timeout, TimeUnit unit) {
        return rateLimiter.tryAcquire(timeout, unit);
    }
}
```

### 1.3 使用方式

```java
// 获取每秒 100 个令牌的限流器
RateLimiter limiter = RateLimiter.getInstance("api:user", 100.0);

// 非阻塞尝试获取
if (limiter.tryAcquire()) {
    // 有令牌，放行
} else {
    // 无令牌，拒绝请求
}

// 带超时等待
if (limiter.tryAcquire(1, TimeUnit.SECONDS)) {
    // 等待 1 秒内获取到令牌
}
```

### 1.4 特点总结

| 特性 | 说明 |
|------|------|
| **算法** | 令牌桶（Token Bucket） |
| **底层库** | Guava RateLimiter |
| **作用域** | 单机（JVM 内） |
| **实例缓存** | 支持（ConcurrentMap） |
| **线程安全** | ✅ |
| **当前状态** | 工具类已实现，尚未集成到业务逻辑 |

## 二、当前方案的局限性

```
┌─────────────────────────────────────────────────────────┐
│                     单机部署                             │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐            │
│  │ 实例 A   │  │ 实例 B   │  │ 实例 C   │            │
│  │ 100 QPS  │  │ 100 QPS  │  │ 100 QPS  │            │
│  └──────────┘  └──────────┘  └──────────┘            │
│       ↓            ↓            ↓                      │
│  各实例独立计数，总请求 = 300 QPS（无法统一限流）       │
└─────────────────────────────────────────────────────────┘
```

- 每个 JVM 实例有独立的令牌桶计数
- 多实例部署时无法做到全局统一限流
- 适合场景：单实例部署，或允许各实例独立限流

## 三、其他实现方案

### 3.1 方案对比

| 方案 | 作用域 | 实现难度 | 依赖 | 性能 | 适用场景 |
|------|--------|----------|------|------|----------|
| **Guava RateLimiter** | 单机 | ⭐ | Guava | 极高 | 单实例、无集群需求 |
| **Redisson RRateLimiter** | 集群 | ⭐⭐ | Redisson | 高 | 分布式集群 |
| **Lua + Redis** | 集群 | ⭐⭐⭐ | Redis | 高 | 高度定制化需求 |
| **bucket4j** | 可扩展 | ⭐⭐ | bucket4j | 高 | 复杂限流规则 |
| **Sentinel** | 集群 | ⭐⭐⭐ | Sentinel | 高 | 阿里系、需熔断功能 |
| **Spring Cloud Gateway** | 网关层 | ⭐⭐ | Gateway | 高 | API 网关统一限流 |

### 3.2 方案一：Redisson RRateLimiter（推荐）

**项目已有 Redisson 依赖，改动最小**

```java
@Service
public class DistributedRateLimiter {

    @Autowired
    private RedissonClient redissonClient;

    /**
     * 获取分布式限流器
     * @param key 限流器唯一标识
     * @param rate 速率
     * @param rateInterval 时间间隔
     * @param unit 时间单位
     */
    public RRateLimiter getLimiter(String key, long rate, long rateInterval, RateIntervalUnit unit) {
        RRateLimiter limiter = redissonClient.getRateLimiter(key);
        // 设置速率（OVERALL 表示全局共享）
        limiter.trySetRate(RateType.OVERALL, rate, rateInterval, unit);
        return limiter;
    }

    /**
     * 尝试获取令牌
     */
    public boolean tryAcquire(String key, long rate) {
        RRateLimiter limiter = getLimiter(key, rate, 1, RateIntervalUnit.SECONDS);
        return limiter.tryAcquire();
    }

    /**
     * 带超时获取
     */
    public boolean tryAcquire(String key, long rate, long timeout, TimeUnit unit) {
        RRateLimiter limiter = getLimiter(key, rate, 1, RateIntervalUnit.SECONDS);
        return limiter.tryAcquire(timeout, unit);
    }
}
```

**使用示例**：

```java
@Autowired
private DistributedRateLimiter rateLimiter;

@PostMapping("/api/action")
public Result doAction() {
    // 每秒允许 100 次
    if (!rateLimiter.tryAcquire("api:action", 100)) {
        return Result.fail("请求过于频繁，请稍后重试");
    }
    // 业务逻辑
    return Result.ok();
}
```

**优点**：
- 项目已有 Redisson 依赖
- Redis 存储，天然支持集群
- 所有实例共享同一计数器
- 线程安全，性能优秀

**缺点**：
- 依赖 Redis

### 3.3 方案二：Lua + Redis 自研

**完全自控，灵活度高**

```java
@Component
public class LuaRateLimiter {

    @Autowired
    private StringRedisTemplate redisTemplate;

    // Lua 脚本：令牌桶算法
    private static final String RATE_LIMIT_SCRIPT = """
        local key = KEYS[1]           -- 限流 key
        local capacity = tonumber(ARGV[1])      -- 桶容量
        local refillRate = tonumber(ARGV[2])    -- 每秒补充令牌数
        local now = tonumber(ARGV[3])           -- 当前时间戳（毫秒）
        local requested = tonumber(ARGV[4])    -- 请求令牌数

        -- 获取当前状态
        local bucket = redis.call('HMGET', key, 'tokens', 'lastTime')
        local tokens = tonumber(bucket[1]) or capacity
        local lastTime = tonumber(bucket[2]) or now

        -- 计算应该补充的令牌数
        local elapsed = (now - lastTime) / 1000.0
        local filledTokens = math.min(capacity, tokens + (elapsed * refillRate))

        -- 尝试获取令牌
        if filledTokens >= requested then
            local newTokens = filledTokens - requested
            redis.call('HMSET', key, 'tokens', newTokens, 'lastTime', now)
            redis.call('EXPIRE', key, 60)  -- 过期时间
            return 1  -- 允许
        else
            return 0  -- 拒绝
        end
        """;

    public boolean tryAcquire(String key, int capacity, int refillRate, int permits) {
        DefaultRedisScript<Long> script = new DefaultRedisScript<>(RATE_LIMIT_SCRIPT, Long.class);
        Long result = redisTemplate.execute(
            script,
            Collections.singletonList(key),
            capacity, refillRate, System.currentTimeMillis(), permits
        );
        return result != null && result == 1;
    }
}
```

**使用示例**：

```java
@Autowired
private LuaRateLimiter rateLimiter;

@PostMapping("/api/action")
public Result doAction() {
    // 桶容量 100，每秒补充 100 个令牌，每次请求 1 个
    if (!rateLimiter.tryAcquire("rate:action", 100, 100, 1)) {
        return Result.fail("请求过于频繁");
    }
    return Result.ok();
}
```

**优点**：
- 完全自研，可定制
- 存储在 Redis，支持集群
- 可根据业务调整参数

**缺点**：
- 需要自己实现算法
- 代码量较多

### 3.4 方案三：Bucket4j

**功能丰富的限流库**

```xml
<dependency>
    <groupId>com.bucket4j</groupId>
    <artifactId>bucket4j-core</artifactId>
    <version>8.10.1</version>
</dependency>
<!-- Redis 扩展（集群支持） -->
<dependency>
    <groupId>com.bucket4j</groupId>
    <artifactId>bucket4j-redis</artifactId>
    <version>8.10.1</version>
</dependency>
```

```java
// 单机用法
public class Bucket4jRateLimiter {
    
    private final Map<String, Bucket> buckets = new ConcurrentHashMap<>();

    public boolean tryAcquire(String key, int capacity, int refillPerSecond) {
        Bucket bucket = buckets.computeIfAbsent(key, k -> 
            Bucket.builder()
                .addLimit(Bandwidth.classic(capacity, 
                    Refill.greedy(refillPerSecond, java.time.Duration.ofSeconds(1))))
                .build()
        );
        return bucket.tryConsume(1);
    }
}
```

**优点**：
- 功能丰富（令牌桶、漏桶、固定窗口、滑动窗口）
- 支持 Redis 扩展
- 可与 Spring Boot 集成

**缺点**：
- 需要新增依赖
- 学习成本

### 3.5 方案四：Sentinel（阿里）

**适合需要流量控制 + 熔断降级的场景**

```java
// pom.xml
<dependency>
    <groupId>com.alibaba.csp</groupId>
    <artifactId>sentinel-core</artifactId>
    <version>1.8.8</version>
</dependency>
```

```java
// 定义限流规则
private static void initRules() {
    List<FlowRule> rules = new ArrayList<>();
    FlowRule rule = new FlowRule("api:action")
        .setGrade(RuleConstant.FLOW_GRADE_QPS)
        .setCount(100)  // 每秒 100 QPS
        .setControlBehavior(RuleConstant.CONTROL_BEHAVIOR_DEFAULT);
    rules.add(rule);
    FlowRuleManager.loadRules(rules);
}

// 使用
@PostMapping("/api/action")
public Result doAction() {
    Entry entry = null;
    try {
        entry = SphU.entry("api:action");
        // 业务逻辑
        return Result.ok();
    } catch (BlockException e) {
        return Result.fail("请求过于频繁");
    } finally {
        if (entry != null) {
            entry.exit();
        }
    }
}
```

**优点**：
- 功能全面（限流 + 熔断 + 降级）
- 支持集群
- 配套 Dashboard 可视化

**缺点**：
- 需要新增依赖
- 学习成本较高


## 五、接入 Redisson RRateLimiter 示例

由于项目已引入 Redisson，最推荐的方案是接入 `RRateLimiter`：

### 5.1 工具类

```java
package com.wtlx.utils;

import org.redisson.api.RRateLimiter;
import org.redisson.api.RateIntervalUnit;
import org.redisson.api.RateType;
import org.redisson.api.RedissonClient;
import org.springframework.stereotype.Component;

import javax.annotation.Resource;

@Component
public class RedisRateLimiter {

    @Resource
    private RedissonClient redissonClient;

    /**
     * 尝试获取令牌（非阻塞）
     * @param key 限流 key
     * @param rate 速率（每秒多少令牌）
     * @return true=允许，false=拒绝
     */
    public boolean tryAcquire(String key, long rate) {
        RRateLimiter limiter = redissonClient.getRateLimiter(key);
        // 只在第一次设置速率
        limiter.trySetRate(RateType.OVERALL, rate, 1, RateIntervalUnit.SECONDS);
        return limiter.tryAcquire();
    }

    /**
     * 尝试获取令牌（带超时）
     */
    public boolean tryAcquire(String key, long rate, long timeout, java.util.concurrent.TimeUnit unit) {
        RRateLimiter limiter = redissonClient.getRateLimiter(key);
        limiter.trySetRate(RateType.OVERALL, rate, 1, RateIntervalUnit.SECONDS);
        return limiter.tryAcquire(timeout, unit);
    }

    /**
     * 阻塞获取（获取到才返回）
     */
    public void acquire(String key, long rate) {
        RRateLimiter limiter = redissonClient.getRateLimiter(key);
        limiter.trySetRate(RateType.OVERALL, rate, 1, RateIntervalUnit.SECONDS);
        limiter.acquire();
    }
}
```

### 5.2 使用示例

```java
@Resource
private RedisRateLimiter rateLimiter;

@PostMapping("/blog")
public Result saveBlog(@RequestBody Blog blog) {
    // 全局限流：每秒最多 100 次
    if (!rateLimiter.tryAcquire("rate:blog:save", 100)) {
        return Result.fail("请求过于频繁，请稍后重试");
    }
    return blogService.saveBlog(blog);
}

// 用户维度限流
@GetMapping("/hot")
public Result queryHotBlog(...) {
    Long userId = UserHolder.getUser().getId();
    if (!rateLimiter.tryAcquire("rate:user:" + userId, 10)) {
        return Result.fail("您的请求过于频繁");
    }
    return blogService.queryHotBlog(current);
}
```

## 六、总结

| 维度 | 当前方案 | 推荐升级方案 |
|------|----------|--------------|
| **实现方式** | Guava 封装 | Redisson RRateLimiter |
| **作用域** | 单机 | 集群全局 |
| **代码改动** | 无 | 小 |
| **依赖** | Guava | Redisson（已引入） |
| **推荐指数** | ⭐⭐ | ⭐⭐⭐⭐⭐ |
